# Architecture

- Routes autoload from `src/routes`, plugins from `src/plugins`. Libraries in `src/lib`, Typebox types in `src/types`.
- Uses [Typebox](https://github.com/sinclairzx81/typebox) for JSON-schema-derived TypeScript types. Convention: `SomeThing` is the schema, `SomeThingType` the inferred TS type.
- A single MongoDB `queue` collection holds outbound email and SMS notifications, so API and ElasticSearch work is not blocked by ATV errors, network lag, or SMTP/Dialogi outages.
- The `statistics` collection holds one document per site per day, containing aggregate counters for subscription lifecycle events plus a daily measurement of the live subscription counts. It exists because `subscription` is a current-state store — subscriptions are hard-deleted on unsubscribe and on expiry — and so cannot answer how many of anything happened during a past period. Counters are written inline by whatever causes the event, with no aggregation job. Documents carry no identifiers and no timestamp finer than a day, so they are anonymous by construction.
- **Production runs Azure Cosmos DB for MongoDB; local and CI run `mongo:latest`.** Two consequences. Cosmos does not support `$jsonSchema`, so the collection validators in `hav:init-mongodb` are a dev and CI safety net only — anything they guarantee has to be enforced in code as well, and `hav:init-mongodb` reports rather than fails when it cannot apply one. Cosmos also indexes only `_id` by default and needs an index on any field it is asked to sort by, so queries are written to lean on `_id`: `statistics` documents are keyed `${site_id}:${day}`, which makes a range scan of `_id` answer both "this site's days between X and Y" and the ordering that depends on, with no index to create. Treat a missing index as a performance question, never a correctness one.
- Adding, confirming, renewing, and deleting subscriptions happen through the REST API.
- ElasticSearch queries, notification delivery, and expired-subscription cleanup run as cron scripts. Cleanup uses each site's `maxAge` / `unconfirmedMaxAge`.
- Email templates live under `src/templates/<templatePath>/*.html`, SMS templates under `src/templates/<templatePath>/sms/*.txt`. There is one template file per message type; per-language strings come from the site config's `translations` map, with the subscription's `lang` exposed as a template variable. To customize a site's templates, copy the folder and update `mail.templatePath` in its config.
